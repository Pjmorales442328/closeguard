How a close runs

  1. Books loaded

    {{ n_bank }} bank lines and {{ n_ledger }} open invoices. Exact-match rules pair what they can.

  2. Agent proposes

    The AI suggests matches for the rest. Memos are read as data, never as instructions.

  3. Gate checks

    {{ n_rules }} rules, fail closed. A refusal says why in plain words and shows the evidence.

  4. Human approves

    A controller or CFO signs off. The agent can never approve its own work.

  5. Posted and verified

    Entries can only be added, never edited. A second, read-only check reads every entry back and confirms nothing changed.

Known limits: what this does not claim

  • All data is synthetic: a fictional company, vendors and bank, with 30 faults planted on purpose.
  • The memo filter is a tripwire, not a wall. {% if hb %}{% set a = hb.attacks %}On a blind set it had never seen, {{ (100 * a.passed / a.trials)|round|int }}% of attack texts passed unflagged (measured panel above).{% else %}On a blind set it had never seen, some attack texts passed unflagged.{% endif %} A memo can still never change an amount, an invoice or an approval.
  • A second model added no catch the gate had not already made on our data.
  • The model price per token is unverified, and the human time per close is still to be measured.
  • It is not an accounting system and has no bank connection; it reads CSV exports.
